## 1. 文档与既有代码的差异裁决

实施前工作区里已存在一份**半成品**实现（另一会话按 `docs/15-全栈Web交付支持技术方案.md`
做的），与目标文档在**同一个概念上用了两套命名**。差异与裁决如下：

| # | 差异点 | 裁决 | 理由 |
|---|---|---|---|
| 1 | 字段名 `delivery_mode`（`library/web_api/web_fullstack`）vs `delivery_shape`（`backend_only/full_stack_ssr/full_stack_spa`） | **统一为 `delivery_shape`**；`delivery_mode` 保留为**输入侧兼容别名**，在 `mas/intent.py` 一次性翻译 | 三值枚举能表达 A/B 档（SSR vs 浏览器前端）的区分，这是本次需求的核心；旧枚举只有一个 `web_fullstack`，无法表达「B 档必须如实失败」 |
| 2 | 门禁第 9 条引用了 `ui_evidence`，但**没有任何节点发布它** | 改为两条 criterion，并让 tester **任何形态都发布** `ui_evidence` | `expr.py` 的 BoolOp 不短路求值，字段缺失会让整条 criterion 判失败——**实测改动前 174 个用例里 13 个因此失败** |
| 3 | 文档 §3.3 表格说 `backend_only`「要求 language 含 python」，但 §4 补丁 2 的代码把 `backend_only/ssr` 一律判 `gap=0` | **按语言分片匹配，保留 python 通道要求** | 后者会让 `"TypeScript + React"` 的 SSR 用 Python 测试假通过，与文档自身的诚实性底线（验收 #8）冲突 |
| 4 | 三值枚举无法表达「纯后端 HTTP 服务也需要网络豁免」（`web_api` → `backend_only` 后豁免丢失） | **遵从文档**：`backend_only` 仍报 major | 文档 §8 验收 #3 明确要求「backend_only 需求里写 `import socket` → 仍报 major」；记为已知取舍 |
| 5 | 另一会话已实现的 `mas/uiprober.py`（真 Playwright MCP 采集器） | **保留并适配**，不删除 | 是真实可用的浏览器证据采集实现；只把它的调用点从 `web_fullstack` 改为按 `delivery_shape` 触发 |

## 3. 边界处理与关键日志

| 场景 | 处理 | 可观测点 |
|---|---|---|
| 需求未声明 / 声明了非法形态 | 注入 `backend_only`（安全默认，行为零变更） | 事件 `intent_fallback`（severity=warning，带 raw 值） |
| L1 规则预分类 | 只作提示，不覆盖 LLM 判定；命中词入事件 | 事件 `intent_classified` |
| 网络模块豁免生效 | 只降 `network_import` 一条，其余规则不变 | 事件 `network_finding_relaxed`（记 from/to/条数/形态来源） |
| 前端产物有静态问题 | 独立采集，不与 Python AST 混在一起 | 事件 `web_static_evidence` |
| SPA 但浏览器通道不可用 | `failed_asserts=1` + `asserts=[]`，**判失败** | 事件 `test_ui_evidence_incomplete`；门禁第 10 条拦 |
| 测试文件写入被权限拒绝 | 跳过该文件继续写其余，不崩节点 | 事件 `test_file_write_denied` |
| `ui_evidence` 缺失（回归防线） | 单元测试 `test_missing_ui_evidence_would_break_even_backend_only` 固化 | — |

## 6. 回滚方式

回退：

```bash

cp -f .bak-before-delivery-shape-20261015/config/*.yaml       config/
cp -f .bak-before-delivery-shape-20261015/config/profiles/*.yaml config/profiles/
cp -f .bak-before-delivery-shape-20261015/config/roles/*.yaml    config/roles/

```

**第 2 选择（分层回退，按风险从低到高）**：

| 想撤掉什么 | 怎么撤 | 影响 |
|---|---|---|
| 只撤前端静态证据 | 删 `reviewer._web_asset_findings` 的两处调用 | 其余不受影响 |
| 只撤三条 Web 生命周期规则 | 把 `ReviewerAgent._WEB_ONLY_SEVERITY` 置空 dict | `backend_only` 与现网一致，SSR 少三类检查 |
| 只撤网络豁免 | `_analysis_policies` 里去掉 `network_import` 那一行 | 前后端需求会被 major 拦回改造前行为 |
| 只撤门禁两条 criterion | 从 `flow.yaml` / `strict.yaml` / `lean.yaml` 删掉即可（配置加载期校验，写错启动即报错） | 形态判定与证据仍留痕，只是不再进门禁 |

> 注意：`ui_evidence` 的**无条件发布不能单独回退**——删掉它会让引用它的两条 criterion
> 在 `backend_only` 任务上也判失败（`expr` BoolOp 不短路）。要撤就同时撤 criterion 与发布。

## 7. 已知限制（如实标注）

1. **B 档浏览器采集器未端到端实测**：`mas/uiprober.py` 的代码链路存在，但本机 `config/mcp.yaml`
   的 `servers: []` 为空、`runtime.ui_probe.enabled: false`，**没有真实跑过一次浏览器采集**。
   因此 `full_stack_spa` 当前必然走「证据不足 → 判失败」分支（这是设计意图，不是缺陷）。
2. **JS 静态检查只是括号配平**：本机无 node，`js_syntax_error` 是弱证据，finding message 里已写明。
3. **框架只执行一个测试文件**：`tester.apply` 的 `test_file` 取 `files` 中最后一个 `tests/` 项。
   若模型把用例分散到多个文件，覆盖率按单文件统计会不达标。这是**既有框架行为**，本次只在
   Web 执行协议里加了「全部用例写进同一个文件」的约束（prompt 层面），未改执行代码。
4. **`web_api` 语义收窄**：旧枚举里的"纯 HTTP 接口服务"归入 `backend_only` 后不再享有网络豁免，
   按文档验收 #3 执行。若后续要支持这类需求，需给三值枚举再加一档（属新需求，不在本次范围）。

### 8.2 端到端（真实 LLM，`examples/requirements/web_todo_app.md`，lean profile）

第 1 次运行 `20261015-115714-81ec`：**test 节点两次崩溃**

```
node_error: SandboxError: 角色 tester 无 can_write_code 权限（目标: serve.py）
```

根因：`ui_service_cmd` / `ui_checks` 两个契约字段被无条件下发（默认值 `python serve.py`），
诱导模型在 `files` 里输出 `serve.py`，而 tester 的 `can_write_code: false` → 写入即抛异常 → 整个节点崩。
**修复**：两个字段从静态契约移除、浏览器协议段改为仅 `full_stack_spa` 注入；
同时让被权限拒绝的单文件写入跳过并记账，不再拖垮节点。

第 2 次运行 `20261015-122842-de18`：链路跑通，产物符合预期
