## 一、最终版（5 条 + 规模行）

**配置驱动的多 Agent 任务协作系统（MAS）**　个人项目　2026.09–2026.10

- 5 个角色 Agent（产品、研发、评审、测试、报告）串起从需求评估到报告归档的 8 节点流水线，节点、流转、门禁、回退全部由 YAML 声明，换流程只写和基础配置不一样的部分：严格模式加一道方案评审变 9 个节点，精简模式去掉代码审查剩 7 个，删掉的节点上下游自动接上，调度代码不用改。角色之间只经版本化黑板与消息总线通信，第三方依赖只有 PyYAML。

- 验收不认模型自述，只认跑出来的证据：10 条门禁判据写成表达式，由 AST 白名单求值器在黑板快照上求值（禁赋值、导入、方法调用），核对用例通过率、功能 / 异常 / 边界三类覆盖率、缺陷与需求歧义是否清零；再叠 18 条 AST 静态规则与前端资产检查，全部放在路径隔离、命令白名单、敏感环境变量剔除、rlimit 四层沙箱里真实执行。

- 长任务与 API 进程解耦：Redis Streams 同时承载运行队列与 Agent 消息，每个角色一个独立消费组，消息扇出到各自邮箱；ACK、PEL 闲置认领、5s / 30s / 120s 阶梯重投、死信队列兜底，至少一次投递语义下按 run_summary 幂等。MySQL 8 建 6 张带索引的投影表，实时写 UPSERT、历史迁移 INSERT IGNORE，防止陈旧快照回滚计数；文件系统仍是证据的唯一真相源，数据库连不上只降级、不抛异常。

- 沉淀 20 个技能（5 个自研 + 15 个由幂等脚本从开源 superpowers 适配生成），按关键词、意图、节点、角色、依赖产物五类 trigger 匹配，命中即把 SKILL.md 全文注入 Prompt——不做摘要转述，避免与原文漂移；单节点最多 3 篇、8.8 万字符预算按「满配不截断」标定，实测单次注入 0.6k–37k 字符。每次命中落 skill_matched 事件并在 Prompt 头部留痕，可回溯；真实运行中命中注入 63 次、12 个技能被触发。另实现把技能脚本注册为模型工具的调用轨道（默认关闭）。

- 手写 SSE 流式客户端绕开网关对非流式请求的 300s 总时长上限，用 reasoning_effort 逐级降级治理思考链吃满输出预算的问题，累计 432 次真实模型调用、4 个模型、13 次降级重发。三级经验库按相关性 0.45、置信度 0.25、频次 0.15、新鲜度 0.15 加权检索注入 Prompt，运行结果反向修正经验置信度，累计 387 次经验强化回写。

规模：43 个模块、1.7 万行 Python、373 条自测，47 次完整运行验证。

## 四、技能体系的口径提醒（面试防翻车）

1. **不能说「5 个自研技能全部命中」**。真实运行被命中的 12 个技能 = 4 个自研（demo-delivery 24 次、evidence-cited-review 20、spec-scope-guard 12、contract-schema-guard 9）+ 8 个 sp-*；自研的 graceful-input-degradation 从未被命中过。安全的说法：「20 个技能里 12 个在真实运行中被触发过」。
2. **不能说「function calling 已上线」**。工具轨道（声明 `tool.script` 的技能注册为 `skill_<id>` 工具、沙箱执行、stdout 回灌）已实现并有单测，但 `tools_enabled=false` 默认关。被问原因：tools 与 response_format 互斥，节点需要结构化 JSON 交付，所以主线走全文注入。
3. **为什么全文注入而不是摘要**：转述会与上游原文漂移（本项目吃过亏：手写 steps 摘要与正文漂移后删掉）；预算按「max_items=3 时最大三篇正文合计 80,895 字符」标定 88,000，保证满配永不截断，实测各节点注入 0.6k–37k。
4. **证据链完整**：每次命中落 skill_matched 事件（含每个技能 body_chars 与是否截断）+ Prompt 文件头部 `skills=[...]` 标记 + 注入段正文，三者可互相对照。
