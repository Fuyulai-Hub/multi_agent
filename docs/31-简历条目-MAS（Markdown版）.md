# 配置驱动的多 Agent 任务协作系统（MAS）

**个人项目** ｜ 2026.9 – 2026.10

> 把「需求评估 → 方案设计 → 编码 → 代码审查 → 测试 → 缺陷修复 → 验收 → 报告」这条原本靠人来回传递的软件交付链路，做成一条由配置描述的自动流水线。五个角色 Agent 分工承担各段职责，做不下去时按规则退回重做；验收只认沙箱里真实跑出来的结果，不认模型自述。

---

## 核心工作

### 一、多角色协作：角色之间不互相调用

- 产品、研发、评审、测试、报告五个角色各管一段职责，彼此**不直接调用**，只通过**共享黑板**（交付物按版本存放，可追溯谁在第几轮改了什么）与**消息总线**（广播、定向通知、问答）协作。
- 支持三条回退路径：审查不通过退回研发修改、测试失败退回研发修复后复测、验收不通过退回上一步重做；回退次数与升级策略可配置，用尽时按既定策略收尾并给出未通过原因，不会无限循环。
- 除一个 YAML 解析库外不引入第三方依赖，其余全部使用标准库实现。

### 二、流程由配置决定，不写死在代码里

- 节点、走向、每段输入输出、验收条件、回退次数全部声明在配置文件中。要插入一个「技术方案评审」环节，或把「代码审查」环节整个去掉，只改配置即可——**被去掉的节点，原本指向它的连线会自动接到下一步**，调度代码一行不动。
- 配置在加载阶段就做校验：写错的验收条件、指向不存在节点的流转、未定义的角色，启动时直接报错，而不是跑到一半才崩。

### 三、验收只认执行结果，不认模型自述

- 验收条件写成可读表达式（如「边界用例必须全覆盖」「未关闭缺陷必须为零」「需求歧义必须全部闭环」），由一个**只能读数据、不能执行任何代码的求值器**判定——只允许读取产物字段与少数内置函数，赋值、导入、方法调用一律拒绝，避免「配置」变成任意代码执行的入口。
- 配合语法树静态检查，扫描文档缺失、类型注解缺失、异常被静默吞掉、危险调用、意外外连依赖等问题。
- 测试与交付代码在**受限沙箱**里真实运行：限制可访问目录、只放行指定命令（明确拒绝 shell 解释器）、剥离含密钥字样的环境变量、限制 CPU 与内存占用。跑通才算通过。

### 四、长任务与页面解耦，中途崩了也不丢

- 一次真实大模型调用可能跑几十分钟，任务投递到 **Redis 队列**由独立后台进程消费，页面只负责提交与查看，关掉网页不会中断流程。
- 消费采用**「至少处理一次」**语义：失败按退避策略重试，超过上限转入**死信队列**等待人工处理；进程崩溃时未确认的任务由其他进程接手；靠运行摘要做**幂等**判断，同一任务不会被重复执行。
- 运行记录、产物版本、经验数据同步进 **MySQL** 便于查询统计，但**文件始终是唯一事实来源**；数据库连不上只降级为读写文件，不影响流程。

### 五、接真实大模型踩过的坑，都固化成了机制

- **网关对单次请求有总时长限制**：非流式的长生成会被掐断、内容全丢，改为流式接收后同样的任务能完整返回。
- **推理模型的思考过程同样占用输出额度**：思考过长会把额度吃光、正文变成空字符串，于是加了「逐级降低推理强度再重发」的降级链，让任务收敛而非直接失败。
- **失败经验沉淀复用**：每次运行中的驳回、缺陷、测试失败会被提炼成经验条目，按相关性、置信度、使用次数、新鲜度加权检索后注入后续任务的提示词；运行结果反过来修正经验置信度——被采纳的加分，没能预防失败的降权。

## 技术栈

| 层面 | 选型 |
| --- | --- |
| 语言与依赖 | Python；除一个 YAML 解析库外全部使用标准库 |
| 编排 | 配置驱动的状态机、共享黑板、消息总线 |
| 校验 | 语法树白名单求值器、语法树静态分析、受限沙箱执行 |
| 服务化 | Redis 队列与消息流、独立后台消费进程、MySQL 索引层 |
| 模型接入 | 手写流式 HTTP 客户端、推理强度降级链、工具调用通道 |
| 界面 | 纯标准库实现的本地控制台，可查看运行过程、证据与经验库，支持任务取消 |

---

## 一句话版本

> 用配置描述一条五角色协作的软件交付流水线：流程增删环节不用改代码，验收靠沙箱里真实跑出的结果而不是模型自述，长任务交给独立后台进程消费、崩溃可接手、失败可重试，接真实大模型时把网关超时与思考链吃满输出额度这两个坑都做成了自动降级机制。

## 备注（面试前自查，不写入简历）

本描述已逐项对照代码与运行记录核验。以下内容**有意未写入**，因为当前实现尚未达到可以直接主张的程度：

- 沙箱不提供网络隔离，对外连依赖只做**检测**而非阻断。
- 多个 Agent 之间是串行推进，没有并行执行。
- MCP 工具通道与模型工具调用能力已实现并验证，但默认关闭，未作为常规运行路径。
- 真实大模型下「长内容生成 + 刚性验收」的通过率尚不稳定，主要瓶颈是长生成被思考链占用额度、以及浏览器级界面证据通道尚未接入时门禁会如实判失败。
