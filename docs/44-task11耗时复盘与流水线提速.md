# 44 · task11 运行耗时复盘与流水线提速（不改验收口径）

本轮对象：`task11-slink-fullstack-01`（`web_shortlink_fullstack`），
`verdict=pass`，总耗时 **13145.39s = 219.1 分钟**。
本文只回答两件事：**时间花在哪**、**哪些能在不降低交付质量的前提下省掉**。

正确性类缺陷（R1 签名密钥、R2 runner 绕过类级夹具、R3 间接继承识别、R4 HTTP 映射误判）
及真实验收证据已在 `docs/43-task11短链接SSR真实验收与流水线缺陷修复.md` 记录，本文不重复。
本文新增的是**耗时治理**：隐藏用例生成预算、冻结套件跳过生成、缺陷闭环诚实性、
审查摘要对齐、研发提示补 docstring 契约。

## 0. 结论

1. **85.0% 的时间在等大模型**：节点 LLM 调用 6182.1s（103.0 分钟，47.0%）+
   隐藏用例生成 4987s（83.1 分钟，37.9%）；框架自身执行/门禁等非 LLM 开销
   只有约 6.4 分钟（2.9%）。
2. **隐藏用例生成一次尝试吃了 69.9 分钟**（无单次预算，≈2×1800s 超时后才成功），
   是单项最大黑洞；该调用此前**完全没有 trace**，只能靠时间戳反推。
3. **冻结测试套件后仍会重新生成**：test iter03/04/05 共 1657.9s（27.6 分钟）生成，
   `apply()` 随即整份丢弃（`test_generation_ignored`）。
4. **假阻塞/假失败制造返工链**：review iter1 的 38 项阻塞里 34 项是缺 docstring、
   4 项是 HTTP 功能点误判 → implement iter2（12.8 分钟）+ 3 轮测试重跑 +
   optimize 空转（9.3 分钟），整条链约 52 分钟。
5. 本轮可避免耗时约 **112.6 分钟（51.4%）**；剩余是必要生成、门禁、报告与
   人工终止空窗（26.5 分钟）。按新逻辑推算同类任务约 **106 分钟**（无人工空窗约 80 分钟），
   但**没有用真实 LLM 重跑全流程**验证，属推算，见 §8。

设计边界：

- **只省等待，不放宽口径**。预算到期返回失败（`timed_out`），不是“超时算过”；
  冻结跳过执行的是同一份冻结副本、同一 `test_hash`，证据链不变。
- **SPA 不跳过**：浏览器证据依赖生成产物里的 `ui_checks` / `ui_service_cmd`，
  跳过后 `_collect_ui_evidence` 会按证据不足判失败。声明 `backend_only` 但文件
  探测升级为 SPA 时同样不跳过（fail-closed）。
- **缺陷不许无证据闭环**：只有本轮真实执行到该用例且通过才记 `fixed`；
  用例随套件重生成消失时记 `stale`（不计 open、也不计 fixed），原实现会直接记 fixed。

## 6. 预期收益（推算，不是实测）

| 项 | 本轮成本 | 新逻辑下 | 本轮可省 |
|---|---:|---:|---:|
| 隐藏生成首轮 | 69.9 min | 单次上限 15 min，总上限 45 min | 54.9 min（按 15 min 截断） |
| 假阻塞返工链（implement2 + test3-5 + review2 + optimize） | 52.1 min | 不再触发（R4 + docstring 提示） | 52.1 min |
| test iter1 覆盖修复 | 5.6 min | R3 已修，不再误判 | 5.6 min |
| **合计** | | | **≈112.6 min（51.4%）** |

- 冻结跳过（27.6 min）已包含在返工链的 test3-5 里，上表不重复计入；
  它的独立价值在“真实缺陷修复后复测”场景：每次复测省 6.4–12.4 分钟生成。
- 人工终止空窗 26.5 分钟不属代码优化收益；若流程无需人工介入，同类任务推算
  219.1 − 112.6 − 26.5 ≈ **80 分钟**；含人工空窗则约 **106 分钟**。
- 隐藏生成的结构修复（13.2 分钟）仍是必要成本，未计入节省。

## 7. 为什么不是“用降质换速度”

1. 跳过生成的条件是「冻结清单签名有效 + 协商已闭环 + 上一轮报告与当前套件
   `test_hash` 一致 + 非 SPA」；执行集合、runner、断言、attestation、门禁 18 条全部不变。
2. 预算只限制等待时长；超时按失败落账，仍会触发回退/重生成，不存在“超时算过”。
3. 缺陷闭环改为“必须真实执行到用例且通过”；`stale` 只用于“用例已不在新套件”
   且不计入已修复，避免把没复测写成修好了。
4. 审查否决结论前置只改摘要展示顺序，`verdict`/`blocking` 仍由框架确定性证据重算。

## 8. 未验证项与边界（如实披露）

- **未用真实 LLM 重跑全流程**：本轮优化后只做了离线/冻结数据复验与单测；
  §6 的节省是推算。真实收益受端点波动影响（同一 DeepSeek 端点单节点曾达 68 分钟）。
- 复验中发现并修掉一个**只在真实运行暴露**的缺陷：tester 感知清单不含
  `test_report`，第一版跳过逻辑在真实流水线里从未触发（单测因手工注入而绿）。
  现改为读黑板 + 加回归用例；若还有类似“只靠单测构造输入”的短路逻辑，需按同样方式复核。
- 隐藏生成**修复前**的逐次耗时没有记录，69.9/7.3/5.9 分钟按时间戳窗口反推；
  修复后才会逐次落 trace。
- `stale` 缺陷不计入门禁 `bug_reports.open`，但会在 `bug_reports.stale` 与 items 中可见；
  目前门禁表达式未把 stale 作为阻塞项。
- `precomputed_generation` 目前只用于 tester；其他角色的类似“生成后丢弃”路径未审计。
- 本次未改 `stream_total_timeout` 等全局 LLM 参数，避免影响 implement/report 的长生成。
