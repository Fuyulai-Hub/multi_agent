## 配置驱动的多 Agent 软件交付流水线系统（MAS）

**一句话简介**：以 Leader 统一调度 + 5 个角色 Agent 协作，把「需求评估 → 方案设计 → 编码实现 → 代码审查 → 业务测试 → 缺陷修复 → 验收门禁 → 报告归档」全链路自动化，并用事件日志驱动的三级经验库构建可证伪的自学习闭环。

**技术栈**：
`Python 3` / `Multi-Agent System` / `Agent Orchestration` / `Leader-Worker` / `流水线状态机` /
`配置驱动 Configuration-Driven` / `YAML Profile 深合并` / `黑板模式 Blackboard` / `消息总线 Message Bus` /
`发布-订阅` / `请求-应答协商` / `上下文工程 Context Engineering` / `Token 预算管理` /
`分层记忆 L1/L2/L3 Tiered Memory` / `经验库` / `自学习闭环` / `加权检索打分` /
`事件溯源 Event Sourcing` / `JSONL 事件日志` / `可观测性 Observability` / `证据链` /
`AST 静态分析` / `白名单安全求值 Safe Expression Evaluation` / `沙箱执行 subprocess` /
`质量门禁 Quality Gate` / `回退与重试` / `优雅降级` / `升级策略 Escalation` /

`MCP (Model Context Protocol, stdio/sse)` / `零依赖设计` / `unittest` / `飞书 OpenAPI` / `联网搜索`

**项目规模**（可写进项目信息栏）：
Python 3.13 + **PyYAML 为唯一第三方依赖**；核心 `mas/` **12,428 行**（36 个模块，有效代码 10,765 行）；

## 核心职责与成果

**1. 设计配置驱动的 Leader 统一调度架构，把 8 节点交付流水线抽象为 YAML 声明式状态机，实现流程拓扑零代码变更。**
用 `config/flow.yaml` 声明节点/角色/流转边/门禁/回退策略，Leader（`mas/leader.py:233-332`）按配置推进状态机；配合 Profile 深合并（`config.py:58-65`，dict 递归、list 整体覆盖）与「裁剪节点后自动重接流转边」（`_apply_skips`，`config.py:548-574`，按 `pass→success→default→fail` 顺序取被裁节点后继、取不到即抛错而非留悬空边），使 `strict` Profile 插入「技术方案评审」节点（8→9 节点）、`lean` Profile 裁剪「代码审查」节点（8→7 节点、门禁由 10 条收敛到 5 条）全程不改动一行调度代码；配置加载期一次性校验节点引用、流转可达性、自环与门禁表达式语法白名单，把故障前置到启动阶段。

**2. 实现「黑板 + 消息总线」解耦的多 Agent 协作内核，支撑版本化上下文共享、事件广播与请求-应答协商。**
5 个角色 Agent 之间零直接调用：成果写入版本化黑板（`artifacts/<产物>/v*.json` + `latest.json` + sha256 摘要），消息总线支持 `direct` / `broadcast` / `request-response` 三种模式并按 `collaboration.yaml` 的 11 主题广播矩阵分发；每个角色按感知矩阵 `require()` 上游产物，缺失项显式写入 Prompt 要求「按缺失处理，请勿臆造」；测试 Agent 遇需求歧义时经 Leader 中介向研发发起协商（`correlation_id` 关联、预算内一轮一问一答），未闭环歧义直接作为门禁项阻塞验收。

**3. 落地基于 AST 白名单安全求值的证据式验收门禁，用可复现事实替代模型自评打分。**
门禁（`kind: gate`）= 黑板快照上求值 10 条表达式 + reviewer 签署意见**双重判定**；求值器（`mas/expr.py:114-220`）基于 `ast.NodeVisitor` 白名单，仅放行常量/属性/下标/比较/布尔/条件表达式与 14 个内置函数，`generic_visit` 兜底拒绝导入、赋值、lambda、推导式等一切副作用语法，字段缺失返回可读原因而非抛异常。代码审查基于真实 `ast` 静态分析（12 条规则：模块/函数文档字符串、类型注解、裸 except、eval/exec、可变默认参数、函数长度、行宽、未使用导入、TODO 残留、语法错误、需求功能点未实现），判定不受模型随机性影响。

**4. 设计三级经验库（L1/L2/L3）自学习闭环，使经验注入产生可测量、可证伪的行为变化。**
从 `events.jsonl` 规则化提炼 5 类经验（审查拦截→提交前自检、缺陷模式→实现守护、验收未通过→前置校验、歧义协商→编码前澄清、成功路径/效率→选型复用），按「相关性 0.45 + 置信度 0.25 + 频次 0.15 + 新鲜度 0.15（30 天指数衰减）」加权检索；分层注入受「分层预算 L3 420 / L2 360 / L1 260 + 全局 1000 token」双重约束，被跳过的条目进 `skipped` 列表并注明原因（置信度不足/非本次运行/超条数/超预算），可审计「为什么这条没注入」。关键设计：每条经验携带**机器可读的 `action_key`**（如 `guard_calc_shipping__boundary`），由确定性执行体真实消费并改变生成行为，而非依赖模型「自觉」。实测：同需求第二轮运行步数 11→7、缺陷 5→0、审查驳回 1→0（`workspace/knowledge/metrics.jsonl`）。

**5. 构建五层沙箱化代码执行与安全加固，把「模型声称通过」变成「跑出来通过」。**
沙箱（`mas/sandbox.py:118-363`）分层防护：① 路径级 `resolve()` 拒绝越界写入；② 命令级白名单只放行 Python / node 解释器并**硬拒 shell 解释器**（`cmd/sh/bash -c` 可绕过一切路径约束）；③ 环境级剔除含 `KEY/TOKEN/SECRET/PASSWORD` 的变量，防凭据泄露给被测代码；④ 资源级 rlimit（CPU 300s / 虚拟内存 1GB / 单文件 64MB / 进程数 128 防 fork 炸弹）；⑤ 检测级 AST 标记外连依赖（`network_import`）与子进程白名单绕过（`sandbox_command_bypass`）。测试文件执行前先做 AST 体检，把「本机没有 g++」这类**环境问题**、「漏写 `import json`」这类**测试套件缺陷**与真实交付物缺陷区分开——实测 C++ 需求曾 19 条用例全败于 `FileNotFoundError`，原实现误记为 19 个研发缺陷并耗尽回退预算。

## 项目亮点

- **零第三方依赖**：除 PyYAML 外不引入任何包。LLM 调用用 `urllib` 手写 SSE 流式解析；前端用 `http.server` 自建；经验检索自实现中文 bigram 重叠系数 + 同义词扩展（6 组词典），不依赖任何向量库或 embedding 服务。
- **用 SSE 流式绕开网关硬超时**：实测端点网关（openresty）`proxy_read_timeout=300s`，语义是「两次读之间的间隔」而非请求总时长。非流式下模型生成完才吐首字节 → 必 504（实测 3×300s 全空输出）；改流式后 TTFB<1s、chunk 间隔<1s，长代码生成不再受网关上限约束。
- **推理模型输出预算治理**：GLM / DeepSeek 等把 reasoning token 计入 `max_tokens`，思考链打满时正文为空且 `finish_reason=length`。实现 `reasoning_effort` 降级链（`low→high`，实测 low≈33s / high≈115s）+ 空正文根因诊断，把静默失败转成可归因错误；网关超时（504/读超时/连接重置）与 `length` 截断走同一条降级链，不让节点直接崩掉。
- **自学习闭环可证伪**：经验不是拼接进 Prompt 的文本，而是带 `action_key` 的可执行信号。离线确定性 Provider 生成代码前读取本次注入的 `action_key` 集合，命中 `guard_*` 的功能点不再注入缺陷、命中 `avoid_*_docstring` 则首轮补全文档字符串——经验直接改变行为。晋级判据是 `hits × success_rate` 而非纯 hits，避免「反复注入但每次都返工」的经验被推上 L3。
- **全链路证据可追溯**：单次运行产出 7 类证据——事件流（`events.jsonl`）、消息记录（`messages.jsonl`）、Prompt 快照（含注入经验 ID 与 token 估算）、LLM 追踪（provider/model/延迟/tokens/思考链/原始输出）、产物全版本、测试沙箱 `stdout/stderr/result.json`、证据索引 `evidence/index.jsonl`，并汇总为 `run_summary.json` 与 `timeline.md`。
- **安全边界如实标注**：沙箱**不提供网络隔离**（标准库无跨平台网络命名空间方案），`network_import` 规则仅用于「让高危外连依赖可见」供 reviewer 拦截；Windows 下 rlimit 自动跳过并在事件中标注降级。这类「做不到的部分」在代码注释与 finding 消息里写明，不谎报。

## 面试可追问点

1. **为什么不用 Airflow / Dagster 等通用工作流引擎？**
   它们面向数据管道调度，缺少「Agent 产物契约 + 经验注入 + 回退语义」。这里需要的是轻量、零依赖、可被 `unittest` 断言的调度内核——配置错误应在加载期一次性汇总抛出，而不是运行到一半才炸。

2. **黑板并发写如何保证不丢版本？**
   版本号按磁盘 `v*.json` 的 `max+1` 计算，且「算版本 + 落盘」在文件锁内完成（`blackboard.py:86-124`）；跨进程锁在 Windows 用 `msvcrt.locking`、POSIX 用 `fcntl.flock`，超时抛 `FileLockTimeout` 而非静默重试；进程内未命中时回落读盘，保证最终一致。

3. **门禁表达式来自配置文件，如何防止任意代码执行？**
   `ast.NodeVisitor` 白名单实现，只实现 14 类节点，`generic_visit` 兜底拒绝其余一切；`Call` 还额外限定 14 个内置函数名。加载期再跑一遍语法 + 白名单校验（`check_config_expressions`），把问题拦在启动阶段。

4. **`expr.py` 的 `BoolOp` 为什么不短路？**
   `values = [self.visit(v) for v in node.values]` 先求全部值再交给 `all`/`any`。因此门禁里若写「某形态才要求 X」，X 所在的 artifact 必须**恒存在**（框架注入默认值 + 节点无条件发布空 artifact），否则老任务会被批量误判失败——这是实测踩出来的坑，不是理论问题。

5. **经验库如何避免「注入次数多」被误当成「效果好」？**
   晋级判据是 `hits × success_rate ≥ 阈值`，`success_rate` 来自 `reinforce()` 的 positive/negative 反馈；无反馈数据时取中性 0.5，既不因零证据快速晋升，也不把历史经验永久卡在底层。回退时只降权「trigger 与本次失败事件匹配」的经验，避免误伤无关经验。

6. **多轮回退如何防止无限循环？**
   三层兜底：单节点 `max_attempts`（如 `review→implement×3`）、全局 `max_total_rollbacks: 8`、最大步数 `max_steps: 40`；耗尽后按升级策略 `fail_run_and_report` 强制发布 `passed:false` 的门禁结论并继续出具不通过报告，而不是静默挂起。

7. **前端交付如何验证？**
   按 `delivery_shape` 分形态：SSR 形态由测试套件的 HTTP 响应体断言承担 UI 验证；SPA 形态要求经 MCP 真实采集浏览器级证据，通道不可得时**如实判失败**（`failed_asserts=1`），绝不允许退化成「Python 测试全过就放行」。同时用静态规则拦截「模块级 `serve_forever()`」和「写死端口」，避免导入自检被挂死到沙箱超时、并行运行端口冲突。

8. **已知短板（主动说明比回避更有说服力）**
   真实 LLM 模式下「长 JSON 生成 + 刚性门禁」的端到端通过率仍不稳定：`metrics.jsonl` 中 2026-10-11 多条 `openai_compatible` 运行 `acceptance:false`（9~15 步、回退 3~9），而 `offline` 确定性模式稳定通过。批量通过率 `[待补充：需按 provider=openai_compatible 跑批统计得出]`，不要凭印象填数。

## 写简历时的避坑清单

1. **可以**说「实现了 Function Calling（Tool Use）闭环」——当前代码已落地：`toolrunner.py` + `mcp.py` + `llm.py:_generate_with_tools`，支持多轮 `tool_calls → 真实执行 → 结果回传 → 续跑`，轮数上限可配。但注意默认关闭（`system.yaml:47 tools_enabled: false`），且因 `tools` 与 `response_format=json_object` 互斥，默认只对 `intake` 节点下发。
2. **不要**声称「高并发 / 分布式」——Leader 是单进程同步 `while` 循环；运行时引用已改为参数显式传递以支持同一 Leader 实例被复用，但同进程内仍不能并行两个 run。
3. **不要**编造通过率、耗时、团队规模、用户量。代码里没有的，用 `[待补充：...]`。
4. **优先使用可核实的量化项**：12,428 行核心代码 / 287 个自测用例全通过 / 5 个角色 Agent / 8 节点流水线（strict 9、lean 7）/ 10 条门禁表达式（lean 5 条）/ 12 条静态分析规则 / 唯一依赖 PyYAML / 112 条经验累计命中 1,772 次 / 平均置信度 0.802 / 46 次真实运行 / 缺陷闭环实测 15→15、18→18。
