## 2. 后端接口契约

### 2.1 `POST /api/run/cancel` —— 终止进行中的运行

```jsonc
// 请求
{ "run_id": "20261017-012243-d8fe" }
// 200：信号已送达（异步语义：退出在下个节点边界发生）
{ "run_id": "20261017-012243-d8fe", "status": "canceling" }
// 404：不在本服务进行中（已完成，或由 CLI/其他进程启动）——如实报错，不伪造送达
{ "error": "运行 xxx 不在本服务进行中（…）" }
```

实现：模块级注册表 `RUNNING_TASKS: dict[run_id, threading.Event]`。`start_run()` 每次运行创建独立事件并登记，worker 线程 `finally` 注销（成功/异常/终止三条路径都走到）。`cancel_run()` 只做 `event.set()` ——线程安全、幂等（重复点击不报错）。

### 2.2 `POST /api/upload/remove` —— 取消一次已上传文档

```jsonc
// 请求
{ "path": "…/workspace/uploads/53c7824ea2a8__wrong_req.md" }
// 200（文件存在）；幂等：不存在时同样 200 但 removed=false
{ "removed": true, "path": "…" }
// 400：路径越界（只能删 uploads 目录内文件，resolve 后目录校验，拒绝 ../ 穿越）
{ "error": "只能移除 uploads 目录内的文件: …" }
```

## 3. 终止任务：协作式取消的设计决策

### 3.1 为什么不是「杀线程」

Python 无法安全强杀线程（`Thread.kill` 不存在；注入异常只对可控点有效）。Leader 内部持有事件日志、黑盒、经验库等多份带锁状态，强杀会造成半写文件与锁泄漏。因此采用**协作式取消**：信号 + 边界检查，是标准做法且与现有 `finally: tool_runner.close()` 收尾兼容。

### 3.2 终止粒度与延迟

检查点位于**主循环每次迭代开头**（即每个节点开始之前）：

```
while node_id not in terminal and steps < max_steps:
    if cancel_event.is_set(): canceled = True; break   # ← 检查点
    ...执行节点...
```

- 语义：**当前节点会执行完毕再停止**（含其中的 LLM 调用、沙箱执行），不影响其正确性；
- 实测延迟：离线流水线整链约 6s / 11~12 步，点击终止后 1 秒内即完成状态切换（见 §5 场景 B）；
- 若要对「单次 LLM 调用中途」也即时生效，需把事件穿透到 `LLMClient` 的流式读取循环——本次刻意不做（改动面大，且网关流式 chunk 间隔 <1s，收益低）。

### 3.3 取消后的收尾（与「未通过」严格区分）

`summary.canceled=True`、`verdict` 强制 `fail`，并**跳过**三件带副作用的事：终态经验反馈（`_reinforce_injected`）、运行级经验提炼/晋级、知识库指标记录（`knowledge/metrics.jsonl`）。理由：终止的运行没有真实终态，半截数据会污染自学习闭环的可信度。`run_summary.json` / `timeline.md` / `run_summary` 之后的 `run_finished(canceled=true)` 事件**照常落盘**——面板的全部状态呈现都依赖它们。

`RunSummary` 新增字段 `canceled: bool = False`（带默认值，历史 run_summary 反序列化不受影响；未传 `cancel_event` 的调用路径行为逐字节不变）。

## 4. 前端组件与状态处理

### 4.1 取消上传（`#cancel-upload`）

- 显隐只由 `state.upload` 驱动：`syncUploadUi()` 在「上传成功 / 上传失败 / 发送成功 / 点击取消」四处调用，按钮出现在 `#upload-name` 旁；
- 点击 → 立即清前端状态（回到未上传状态，可重新选同一文件）→ 调 `/api/upload/remove`；
- 删除失败**不回滚**前端取消：本地原文件仍在，服务端残留只是多余副本，文案区分「已取消本次上传」与「已取消选择（暂存文件未删除：…）」；
- 从粘贴通道进来的文档同样进入 `state.upload`，按钮同样可见（同一链路）。

### 4.2 终止任务（`#cancel-run`）

- 按钮只在 `detail.finished === false` 时渲染（运行详情顶部工具栏，`renderRunDetail` 内动态生成），点击走 `#run-detail` 事件委托；
- `window.confirm` 二次确认（文案含 run_id 与生效语义）；
- 请求成功 → `cancelingRuns` 集合记录 → 按钮置灰「终止中…（当前节点执行完毕后停止）」→ 纳入 `activeRuns` 轮询；运行真正结束后由 `pollTick` 清理并提示「已终止 xxx：用户手动终止（第 N 步后停止，未参与验收判定）」；
- 请求失败（404，运行实际已结束）→ 清除置灰 + **同时刷新列表与详情**（实测暴露：原实现只刷详情，列表会停在旧「进行中」——已修复，见 §5）；
- 转义防护：`renderCache.runId=null` 强制重绘，保证按钮状态即时切换不被缓存跳过。

### 4.3 状态模型（新增「已终止」与既有状态的关系）

```text
进行中（finished=false）──> 已完成（finished=true, canceled=false）
                        └─> 已终止（finished=true, canceled=true）      ← 新增
                        └─> 异常中断（无 run_summary，服务中断/线程异常）  ← 既有
```

| 呈现位 | 已终止的渲染 | 数据来源 |
| --- | --- | --- |
| 运行列表徽章 | `已终止`（橙 `.badge.canceled`），不显示通过/未通过 | `run.canceled`（`load_runs`） |
| 对话区运行气泡 | 同上 | 同上 |
| 详情验收卡片 | `[验收, 已终止, orange]`（优先于「进行中/异常中断/未通过」判定） | `detail.canceled`（`load_run_detail` 新增顶层字段） |
| 状态栏提示 | 「已终止 xxx：用户手动终止（第 N 步后停止…）」 | `pollTick` |

`load_run_detail` 同时新增顶层 `run_id`（运行中 summary 不存在，终止按钮需要它定位运行——这是实测中发现的必要性）。

### 5.3 浏览器 UI 实测（真实 Chrome，Playwright 驱动，快照取证）

**场景 A（取消上传）**：上传 `wrong_req.md` → 快照出现 `已选择：wrong_req.md（text，…）` + `button "✕ 取消上传"` → 点击 → 快照变为 `已取消本次上传：wrong_req.md（暂存文件已删除）`、按钮消失 → 服务端 `uploads/` 目录 0 个文件。

**场景 B（终止任务）**：发起运行 → 详情出现 `button "■ 终止任务"` → 点击 → confirm 对话框（真实弹出，文案：`确认终止运行 20261017-…？终止将在当前节点执行完毕后生效…`）→ 接受 → 1 秒后快照三处显示「已终止」（状态栏 `已终止 20261017-012243-d8fe：用户手动终止（第 9 步后停止，未参与验收判定）`、列表徽章、详情卡片）→ 服务端 `20261017-012243-d8fe 已终止 canceled=True steps=9`（完整流程 11~12 步，在第 9 步中途终止成功）。

**实测暴露并修复的问题**：点击终止时若运行恰已结束（离线运行整链仅约 6 秒），后端如实返回 404；原前端 404 分支只刷新详情、**列表停在旧「进行中」**。修复：404 分支补 `await loadRuns()` 同步列表（已在复跑中验证修复生效）。

## 6. 已知边界（如实声明）

1. **注册表只覆盖本服务进程发起的运行**：CLI `python -m mas run` 或其他进程启动的运行不在 `RUNNING_TASKS` 中，终止接口对其返回 404（明确报错，非静默失败）。服务重启后孤儿运行同理（其状态由既有 `RUN_STALE_SECONDS` 机制在 600s 后判为中断）。
2. **终止不是「立即中断」**：当前节点执行完毕才停止，延迟 = 当前结点剩余耗时。UI 已把这一语义写进确认文案与按钮提示。
3. **`cancel_event` 为可选参数**：不传时 `Leader.run` 行为与改造前逐字节一致（`test_pipeline` / `test_runtime_isolation` 回归覆盖）。
4. **被终止运行不沉淀经验/指标**：属有意设计（见 §3.3），不是遗漏。
