## 四、面试追问预案

**Q：为什么用 Redis Streams 而不是 List 或 Kafka？**
List 没有消费组和 PEL，做不到「多角色各消费一份」和「worker 崩溃后消息不丢」。Streams 原生消费组 + PEL 刚好覆盖扇出与认领两个需求，且已有 Redis 实例，不引入第二套中间件。Kafka 对这个规模的部署和运维成本不成比例。

**Q：at-least-once 的重复投递怎么处理？**
业务幂等键是 `run_summary.json` 是否存在：worker 领取任务后若发现该 run 已有 summary，直接 ACK 跳过（可能上次崩在 ACK 之前）。重试前会把上次未完成的运行目录归档到 `workspace/run_attempts/` 并清理该 run 的 Agent / 事件流，保证重跑用干净证据链。

**Q：MySQL 和文件谁是权威？**
文件系统是证据层唯一真相源（`events.jsonl` / `artifacts/v*.json`），MySQL 只是可查询投影。因此失败时降级回文件路径，且任何库异常都不抛、只留痕。也正因为 jsonl 可能是陈旧快照，历史迁移用 `INSERT IGNORE` 而非 UPSERT——曾用 UPSERT 迁移把实时 hits 从 999 回滚到 1。

**Q：门禁表达式为什么不用 eval？**
`eval` 能跑任意代码。这里用 AST 遍历，白名单限定语法节点类型与内置函数，`generic_visit` 兜底拒绝一切未声明语法；变量只能走 `artifact.字段.子字段` 点路径，字段缺失返回可读原因而不是抛异常。注意一个已踩的坑：`BoolOp` 不做短路求值，`A or B` 里 B 字段缺失会让整条判失败——所以带条件的门禁必须先保证两侧 artifact 恒存在。

**Q：真实模型下系统稳吗？**
如实说：offline 确定性模式稳定通过；真实模型下「长 JSON 生成 + 刚性门禁」通过率还不稳，47 次运行 19 次过验收。主要瓶颈是长生成被思考链吃掉输出预算、以及前后端交付形态要求的浏览器级 UI 证据通道尚未接入时门禁会如实判失败。这两点都有明确的降级与收尾机制，不靠放宽门禁糊过去。

## 七、易懂版（推荐对外投递使用）

> 原则：只保留读者能理解的规模量级，删掉行数、模块数、用例数、调用次数这类对读者无信息量的数字；
> 术语首次出现即用一句话解释。

```
配置驱动的多 Agent 任务协作系统（MAS）                    2026.9 - 2026.10  个人项目

· 把软件交付做成一条自动流水线：需求评估 → 方案设计 → 编码 → 代码审查 → 测试 → 缺陷修复 →
  验收 → 出报告，由产品、研发、评审、测试、报告五个角色 Agent 分工承担；审查不通过退回研发、
  测试失败退回修复、验收不通过打回重做。角色之间不互相调用，只通过共享产物和消息总线协作，
  每次改动都有版本记录，可追溯到具体环节。除一个 YAML 解析库外不引入第三方依赖。

· 流程由配置决定，不写死在代码里：节点、走向、验收条件、回退次数都声明在配置文件中。要加一个
  「方案评审」环节或去掉「代码审查」环节，改配置即可——被去掉的节点，其上下游连线会自动接上，
  调度代码一行不动。配置加载时就会拦下写错的验收条件、指向不存在节点的流转，把问题挡在启动前。

· 验收只认实际执行结果，不认模型自述：验收条件写成可读表达式（如「边界用例必须全覆盖」），
  由一个只能读数据、不能执行任何代码的求值器在产物快照上判定，避免配置变成任意代码执行入口；
  配合语法树静态检查扫描文档缺失、异常被吞掉、危险调用这类问题。测试与交付代码都在沙箱里真实
  运行——限制工作目录、只放行指定命令、剥离密钥类环境变量、限制资源占用，跑通才算通过。

· 长任务与页面解耦，中途崩了也不丢：任务投递到 Redis 队列，由独立后台进程消费，因此关掉网页
  不会中断正在跑的流程；处理失败按退避策略重试，超过上限转入死信队列等待人工处理；进程崩溃时
  未确认的任务由其他进程接手，并通过运行摘要做幂等，避免同一个任务被重复执行。运行记录与产物
  索引同步进 MySQL 便于查询，但文件仍是唯一事实来源，数据库不可用只降级、不影响流程。

· 接真实大模型踩过的坑都固化成了机制：网关对单次请求有总时长限制，改为流式接收后长任务才不会被
  掐断；推理模型的思考过程同样占用输出额度，思考过长会导致正文为空，于是加了「逐级降低推理强度
  再重发」的降级链。每次运行的失败原因会沉淀为经验，按相关性、置信度、使用次数、新鲜度加权检索，
  注入后续任务的提示词；运行结果再反过来修正经验置信度——被采纳的加分，没能预防失败的降权。
```
