## 1. 容器沙箱与失败关闭

### 实现

- `runtime.sandbox_backend: local | container`；未知值直接抛 `SandboxError`。
- `container` 后端在构造时校验：
  - `runtime.sandbox_container.image` 非空；
  - 容器运行时在 `PATH` 中；
  - 镜像本地存在（`docker image inspect`）。
  - 任一项失败都抛 `SandboxError`，**不降级到宿主执行**。
- `docker run` 关键参数：`--network none`、`--read-only`、`--cap-drop ALL`、
  `--security-opt no-new-privileges`、`--pids-limit`、`--memory`、`--cpus`，
  仅把本次运行的 `run_dir/code` 挂到 `/workspace:rw`，`/tmp` 使用 `noexec,nosuid` tmpfs。
- `docker run` 返回 125（运行时自身故障）→ `SandboxError`，不当作测试失败；
  超时会按容器名执行 `docker rm -f`，避免残留容器继续运行。

### 证据

单元测试（Docker 被 mock，不需要真实 daemon）：

```text
tests.test_sandbox_container: Ran 6 tests ... OK
```

真实 Docker 隔离冒烟（本机 Docker 27.3.1，镜像 `u24:python`，容器内执行）：

```text
exit: 0
NET_BLOCKED
ROOT_READONLY
WORKSPACE_WRITABLE
```

即：网络连接失败、根文件系统不可写、`/workspace` 可写。

### 边界（不要误读）

- `config/system.yaml` 默认仍是 `sandbox_backend: "local"`。本地后端只是路径/命令白名单，
  **不是安全边界**；需要隔离时必须显式切到 `container` 并准备镜像。
- 镜像按 tag 引用，未做 digest 固定；生产应固定 digest 并定期扫描。
- 未启用 gVisor/Firecracker 等更强隔离；Docker daemon 本身仍是高权限信任根。
- 真实冒烟使用本机已有镜像，不等同于对默认 `python:3.12-slim` 的拉取与运行验证。

## 2. 测试冻结与独立验证

### 实现

- `mas/verifier.py` 的 `TestVerifier`：
  - `freeze()` 把生成的测试文件复制到 `frozen_tests/`，对文件集合计算 SHA-256 digest，
    写 `test_manifest.json` 并做 HMAC-SHA256 签名；
  - 执行前 `restore()` 用冻结副本覆盖被修改的测试文件，并记录 `test_freeze_restored`；
  - 执行前检查冻结 hash 是否被改动，不一致则 `invalidate()`；
  - `attest()` 读取真实测试结果，重新计算 passed/failed/coverage/assertions，
    与模型自报不一致、断言为空、签名无效都判 `valid=false`，并写
    `verification_attestation.json`。
- `tester` 把 `verification_attestation` 摘要写入 `test_report`；验收门禁新增两条 criterion：
  - `测试证据通过独立验证`：`test_report.verification_attestation.valid == True`
  - `冻结测试 hash 非空`：`test_report.verification_attestation.test_hash != ''`
- 密钥取 `MAS_VERIFIER_SECRET`；未配置时使用进程内随机密钥。

### 证据

```text
tests.test_verifier: Ran 15 tests ... OK
tests.test_web_delivery: Ran 52 tests ... OK
```

全量回归中，`RealFlowGateTests` 的构造数据已补上 `verification_attestation` 摘要字段；
测试首次暴露的 2 条失败正是新增门禁生效的证据（未发布凭据 → 全部历史任务验收失败），
补 fixture 后转绿。

### 边界

- 未设置 `MAS_VERIFIER_SECRET` 时，进程重启后旧 manifest 的签名无法验证；
  多进程/重启续跑场景必须配置稳定密钥。
- HMAC 只能发现「artifact 被改」，无法抵御能读取密钥并重签的同一权限主体；
  也不等于可信时间戳/外部存证。
- 冻结的是文件内容与执行结果，**不冻结运行时环境**（依赖版本仍靠镜像/锁文件）。

## 3. 检查点、租约与幂等

### 实现

- **检查点**：`Leader.run(..., resume=True)` 读 `<run_dir>/checkpoint.json`；
  - 输入阶段与每次状态迁移后原子写入（临时文件 + fsync + `os.replace`）；
  - 记录 `next_node`、`iterations`、`rollback_counts`、`steps`、`run_state`、
    需求 SHA-256、`started_at`；
  - 恢复时跳过已完成节点与需求摄入，从 `next_node` 继续；
  - 需求文件变化、检查点损坏/版本不符/已完成 → `ConfigError`，失败关闭。
- **事件日志恢复**：`EventLog(resume=True)` 从已有 `events.jsonl` 恢复 seq；
  硬杀留下的半截 JSON 行被跳过，下一条事件不会与 MySQL `(run_id, seq)` 冲突。
- **worker 租约**：`RunLease` 用 Redis `SET NX PX` 获取 `run:<id>` 锁，Lua 校验 token 续期与释放；
  续租线程同时刷新运行注册表心跳（默认 90s TTL），长 LLM 节点不会“看起来死掉”。
- **幂等**：
  - 已有 `run_summary.json` 的任务直接 ACK，不重复执行；
  - 租约被其他 worker 持有 → 不 ACK、不执行，消息留在 PEL 等待重投；
  - 可恢复的运行（checkpoint 为 running 且需求文件存在）不归档、不重置事件流；
  - 不可恢复的半截运行才归档到 `run_attempts/<run_id>/attempt-N-*`；
  - `ConfigError` 转为 `PermanentTaskError`，直接进死信而不是无限重试。
- **取消**：`mas:run:<id>:cancel` 独立于心跳键，心跳短暂过期后重复取消仍然有效。

### 证据

```text
tests.test_checkpoint_resume: Ran 11 tests ... OK
tests.test_store_integration: Ran 16 tests ... OK
tests.test_mq_integration: Ran 6 tests ... OK
```

`test_store_integration` 的 `test_redis_lock_exclusivity` 已加入续租正例、错误 token 续租反例；
`test_build_registry_prefers_redis` 在真实 Redis 下走了 `RedisRunRegistry`，不是内存降级。

### 边界

- 检查点是**节点粒度、至少一次**：节点执行到一半崩溃，恢复后整个节点会重跑；
  节点内部的外部副作用（发消息、写远端系统）仍需自身幂等键。
- 租约默认 TTL 300s、续租 30s；进程被暂停超过 TTL 仍可能被其他 worker 接管，
  Redis 锁不是 fencing token，极端情况下不能阻止旧进程继续写。
- 归档是移动而非删除，长期运行需要独立的清理策略。
- 真实 Redis/MySQL 集成测试已跑通，但未做多机网络分区/时钟漂移演练。

## 4. 面板认证与路径边界

### 实现

- **失败关闭**：`--host` 非 `127.0.0.1/localhost/::1` 时必须设置 `MAS_PANEL_TOKEN`，
  否则打印原因并以退出码 2 拒绝启动。
- **认证**：所有 `/api/*` 支持 `Authorization: Bearer`、`X-Panel-Token`；
  `GET /?token=...` 校验后种 `HttpOnly; SameSite=Strict` Cookie 并 303 回 `/`。
  比较使用 `hmac.compare_digest`。
- **CORS/CSRF**：不再返回 `Access-Control-Allow-Origin: *`；只回显同源或
  `MAS_PANEL_ORIGINS` 白名单。无令牌模式下，跨站 `POST` 直接 403。
- **密钥不回显**：`GET /api/llm` 只返回 `api_key_set` / `api_key_masked`；
  表单留空继续沿用已保存 Key。
- **路径限制**：
  - `requirement_path` 与 `images` 必须 `resolve()` 到 `workspace/uploads/` 内且是已存在文件
    （同时挡住 `..` 与符号链接逃逸）；
  - `profile` 只接受 `[A-Za-z0-9_-]{1,64}`；
  - `run_id` 只接受 `[A-Za-z0-9._-]{1,80}` 且拒绝 `.`/`..`，用于 `/api/run?id=` 与取消接口。
- 响应加 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、
  `Referrer-Policy: no-referrer`；401 带 `WWW-Authenticate: Bearer`。

### 证据

```text
tests.test_panel_security: Ran 23 tests ... OK
```

覆盖：无令牌 401、Bearer/自定义头/Cookie 三种凭据、错误令牌、登录重定向、
静态页公开、白名单 CORS 回显、未知来源无 CORS 授权、跨站 POST 403、
上传目录内路径通过、目录外/穿越/不存在文件拒绝、图片路径拒绝、profile 穿越拒绝、
run_id 穿越拒绝、`/api/llm` 不含明文 Key、非回环无令牌拒绝启动。

启动期失败关闭也已用真实命令验证（不绑定端口即退出）：

```text
$ python frontend/server.py --host 0.0.0.0 --port 0
拒绝启动：--host 0.0.0.0 非回环地址，必须设置环境变量 MAS_PANEL_TOKEN（...）
EXIT:2
```

### 边界

- 只有一个共享令牌，没有用户账号、RBAC、租户隔离和操作审计；
  适合单人或小团队内网，不是多租户控制面。
- 不负责 TLS；对外暴露必须放在 HTTPS 反向代理后，并设置 `X-Forwarded-Proto: https`
  让登录 Cookie 带 `Secure`。
- 静态页面公开（不含运行数据）；知道令牌的人拥有全部 API 能力。
- `/api/llm/test` 会向用户提供的 `base_url` 发请求，仍有 SSRF 面；目前仅靠令牌门槛，
  生产应加域名白名单/出口代理。

## 6. 仍未解决（保持诚实）

1. 默认 `sandbox_backend` 仍是 `local`；切到 `container` 需要准备镜像并接受 Docker 依赖。
2. 没有 TLS、多用户、RBAC、审计与租户配额；面板令牌是单权限共享秘密。
3. 检查点是节点粒度至少一次，不提供 exactly-once；外部副作用需业务幂等键。
4. 没有 fencing token，严格意义上租约仍可能被旧进程“僵尸写入”。
5. 未做故障注入（杀进程、网络分区、时钟漂移）与多机联调；真实 LLM 长节点下的租约行为
   只在单元测试与心跳路径上验证。
6. 评测基准、成本预算、模型网关、CI/CD 与交付人工闸门仍属于 docs/37 的 P1。
