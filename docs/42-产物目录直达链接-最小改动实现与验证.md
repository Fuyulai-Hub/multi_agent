# 42 · 产物目录直达链接（最小改动实现与验证）

## 1. 需求与结论

任务执行结束后（成功 / 失败 / 已终止都算），在结果展示区给出一条直达本次运行产物目录的入口：
能打开就打开系统文件管理器定位到该目录，打不开就展示真实绝对路径并提供一键复制。

已实现并真实验证：后端两个接口（`GET /api/run/artifacts`、`POST /api/run/open`）+ 前端结果区
一条「产物目录」横条（打开链接 / 绝对路径 / 复制按钮）。新增依赖：无（只用标准库 `subprocess`）。

## 2. 为什么不是 `file:///` 链接

浏览器禁止 http(s) 页面导航到本地文件（Chrome 直接报 `Not allowed to load local resource`），
所以 `<a href="file:///...">` 在面板页面上点了没用。真正能「定位到文件夹」的路径是：
让**与产物同机**的面板进程调用系统文件管理器 —— 即 `POST /api/run/open`。
打开失败（远程部署、无桌面、无 `xdg-open`）时接口照常返回真实路径，前端退化为展示 + 复制。

## 3. 后端改动（`frontend/server.py`）

| 位置 | 改动 |
|---|---|
| `resolve_artifact_dir(workspace, run_id)` | 新增。产物目录 = `runs/<id>/artifacts`（各节点产物本体），该目录不存在时回退 `runs/<id>`；返回 `Path.resolve()` 后的绝对路径 + `exists` + `item_count`；run 不存在抛 `ValueError` |
| `reveal_in_file_manager(path)` | 新增。Windows `os.startfile` / macOS `open` / Linux `xdg-open`，返回 `(ok, reason)` |
| `open_artifact_dir(workspace, run_id)` | 新增。先解析并校验目录存在，再打开；返回 `opened` / `reason` / `path` |
| `load_run_detail` 返回体 | 增加 `artifact_dir` 字段（前端渲染数据源，省掉一次额外请求） |
| `GET /api/run/artifacts?id=` | 新增路由。id 非法 400，run 不存在 404，正常 200 |
| `POST /api/run/open` | 新增路由 + POST 白名单登记。body `{run_id}` |

判定口径：`exists` 是**实测**（`Path.is_dir()`），不是拼接出来的应然路径；
`normalize_run_id` 已挡住 `../` 穿越，路径永远落在 `workspace/runs/<id>` 内。

## 4. 前端改动（`frontend/app.js` / `style.css`）

- `renderRunDetail`：在终止按钮条之后插入 `.artifact-dir` 横条 ——
  标签「产物目录」+ 链接「打开目录」(`#open-artifact-dir`) + `<code>` 真实路径 +
  按钮「复制路径」(`#copy-artifact-dir`) + 条目数（`exists=false` 时显示「目录尚未生成」）。
- 事件委托：`#open-artifact-dir` → `POST /api/run/open`；`#copy-artifact-dir` →
  `navigator.clipboard`（非安全上下文降级 `textarea + execCommand`）。
- 结果反馈复用既有 `setComposerStatus`：打开成功 `done`，失败提示原因并让用户复制路径。
- `style.css` 新增 `.artifact-dir*` 五条规则，用既有 CSS 变量（`--panel/--border/--accent`）。

## 6. 未验证项（如实标注）

- **鼠标点击链接的完整浏览器行为未在本机执行**：本机没有 playwright / 浏览器自动化工具
  （`import playwright` → ModuleNotFoundError）。验证方式是拆解到两端：页面 DOM 中
  `#open-artifact-dir` 确实渲染且绑定了事件委托，接口 `POST /api/run/open` 用真实 HTTP 请求
  调用返回 `opened=true`（即 `os.startfile` 被真实调用）。中间的「鼠标点击」一步未模拟。
- **复制按钮的剪贴板写入未在浏览器中执行**：`navigator.clipboard` / `execCommand` 需要真实
  用户手势与焦点环境，headless 下无法断言剪贴板内容；仅验证按钮与 `data-path` 已渲染正确。
- **`os.startfile` 是否真的弹出资源管理器窗口**：接口返回 `opened=true` 只表示系统调用未抛错，
  弹出窗口在有桌面的会话里出现，本次未做视觉确认。
