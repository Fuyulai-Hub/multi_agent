## 一、项目名称与一句话概述

**配置驱动的 Multi-Agent 软件交付流水线系统（MAS）**

> 以 Leader 统一调度 + 5 个角色 Agent 协作，将「需求评估 → 方案设计 → 编码实现 → 代码审查 → 业务测试 → 缺陷修复 → 验收门禁 → 报告归档」全链路自动化，并通过事件日志驱动的分级经验库构建自学习闭环。

**项目定位**（可放一句话在标题后）：
零第三方依赖（仅 PyYAML）的 Python 多 Agent 框架，核心自研 6,789 行；流程节点、协作规则、质量门禁、回退策略全部 YAML 配置化，通过 Profile 切换即可增删流程节点而无需改动调度代码。

## 二、职责与成果（Bullet，动词开头 + 技术方案 + 结果）

> 共 5 条，建议按其投递岗位裁剪到 4 条；每条均可被面试官追问到代码文件级。

**1. 设计配置驱动的 Leader 统一调度架构，将 8 节点交付流水线抽象为 YAML 状态机，实现流程拓扑零代码变更。**
用 `flow.yaml` 声明节点/角色/流转/门禁/回退策略，调度器（`mas/leader.py`）按配置推进状态机；通过 Profile 深合并（`deep_merge`，dict 递归、list 整体覆盖）与「裁剪节点后自动重接流转边」（`_apply_skips`）支持流程可插拔——`strict` Profile 插入「技术方案评审」节点（8→9 节点）、`lean` Profile 裁剪「代码审查」节点（8→7 节点）并收敛门禁（8→3 条）。配置加载期完成结构校验（节点/角色引用/流转目标/自环/门禁表达式语法与白名单），把错误前置到启动阶段而非运行到一半失败。

**2. 构建黑板 + 消息总线解耦的多 Agent 协作机制，实现版本化上下文共享、事件广播与请求-应答协商。**
5 个角色 Agent 互不直接调用：通过版本化共享黑板（`artifacts/<产物>/v1,v2…` + `latest.json` + sha256 摘要）传递成果，通过消息总线支持 direct / broadcast / request-response 三种模式并按配置矩阵分发 11 类关键事件；每个角色按 `perception` 感知矩阵声明可见的上游产物，缺失项显式写入 Prompt 要求「按缺失处理，请勿臆造」。测试 Agent 发现需求歧义时经 Leader 中介向研发发起请求-应答协商（`correlation_id` 关联），未闭环的歧义直接作为门禁项阻塞验收。结果：Agent 间零直接耦合，全部通讯落盘 `messages.jsonl` 可审计。

**3. 实现证据式验收门禁与分级回退容错，用 AST 白名单求值替代模型自评判分。**
门禁（`kind: gate`）由 8 条表达式在黑板快照上求值 + reviewer 签署意见双重判定，表达式求值器（`mas/expr.py`）基于 `ast.NodeVisitor` 白名单实现，仅允许常量/属性/下标/比较/布尔运算与 14 个内置函数，禁用导入、赋值、lambda 等一切副作用语法，字段缺失返回可读原因而非抛异常。不通过时按 per-node 回退策略退回研发修复（`review→implement×3`、`test→optimize×3`、`acceptance→optimize×2`）并计数，超出上限走 `fail_run_and_report` 升级策略仍出具不通过报告；配合全局回退上限 8、最大步数 40 兜底防死循环。代码审查基于真实 `ast` 静态分析（12 条规则：文档字符串、类型注解、裸 except、eval、可变默认参数、函数长度等），不受模型随机性影响。

**4. 设计三级经验库自学习闭环，让经验注入产生可测量、可证伪的行为变化。**
从事件日志规则化提炼 5 类经验（审查拦截 → 提交前自检；缺陷模式 → 实现守护；验收未通过 → 前置校验；歧义协商 → 编码前澄清；成功路径/效率 → 选型复用），按 `相关性 0.45 + 置信度 0.25 + 频次 0.15 + 新鲜度 0.15` 加权检索，分层（L3 全局 / L2 项目域 / L1 本次运行）受「分层预算 + 全局 1000 token 总预算」双重约束注入 Prompt；同源经验按 `scope+action_key` 哈希合并（置信度递增、证据计数累加），命中次数达阈值自动晋级 L1→L2→L3。关键设计：注入的经验携带结构化动作标识（`action_key`），被确定性执行体真实消费（如命中 `guard_calc_shipping__boundary` 则不再注入该边界缺陷）。实测离线回归第二轮运行步数 11→7、缺陷 5→0、审查驳回 1→0（`workspace/knowledge/metrics.jsonl`；仓库测试注释记为 12→7）。

**5. 建设全链路可观测性与容错降级，使每一次 Agent 决策可追溯到证据。**
以事件日志（`events.jsonl`，seq 递增、带 agent/node/iteration/severity/refs）为唯一事实来源，一次运行产出 7 类证据：事件流、消息记录、Prompt 快照（含注入经验 ID 与 token 估算）、LLM 追踪（provider/model/延迟/tokens/思考链/原始输出）、产物全版本、测试沙箱 stdout/stderr/result.json、证据索引 `evidence/index.jsonl`；并生成 `run_summary.json` 与 `timeline.md`。容错方面：Agent 异常统一降级为节点失败并发 `node_error` 事件，沙箱执行带 180s 超时与路径越界校验（拒绝写入工作目录外），门禁字段缺失返回可读失败原因而非崩溃，回退耗尽与步数超限均走升级策略而非静默失败。配套纯标准库前端面板（`http.server`，零额外依赖）提供 7 个只读 API，可视化事件流、门禁判定、经验库与跨轮指标对比。

## 四、面试可展开的技术难点与解法

### 难点 1：配置驱动的状态机，如何在「增删节点」后保证拓扑连通与配置正确性？

**问题**：流程节点、流转边、门禁表达式都写在 YAML 里，用户随便改一处就可能让流程断链、指向不存在的节点，或写出带副作用的门禁表达式——如果等到运行到一半才炸，代价极高。

**解法**：
- **深合并 + 覆盖语义明确**：`deep_merge()` 对 dict 递归合并、list 与标量整体覆盖，这样 Profile 既能改单个字段（如 `review.max_attempts: 4`），也能整体替换门禁清单（`gate.criteria` 是 list，整体覆盖而非追加）。
- **裁剪节点自动重接流转边**：`skip: true` 的节点被移除后，扫描所有指向它的 `transitions`，按 `pass → success → default → fail` 顺序取其被裁节点的后继作为替代；找不到就直接抛配置错误，绝不留下悬空边。同时清理引用了已裁节点的回退策略，避免校验失败。
- **加载期结构校验前置**：`_validate()` 检查入口存在、节点角色已定义、流转目标可达（节点或终止态）、task 节点必须声明 outputs、gate 节点必须声明 criteria、禁止自环（`forbid_self_loop`）、门禁表达式语法与白名单（`check_config_expressions`）——全部问题一次性汇总抛出，而不是遇到第一个就退出。
- **追问可答**：为什么不直接用通用工作流引擎（Airflow/Dagster）？因为它们面向数据管道调度，缺少「Agent 产物契约 + 经验注入 + 回退语义」；这里要的是轻量、零依赖、可被单元测试断言的调度内核。

### 难点 2：多 Agent 的上下文管理与 token 膨胀——如何既不丢上下文，又不撑爆窗口？

**问题**：流水线越往后，上游产物（需求规格、方案、代码清单、审查报告、测试报告、缺陷单）越多，全量塞进 Prompt 会迅速撑爆上下文；但如果截断过多，Agent 又会丢失关键约束，产生「臆造补齐」的幻觉。

**解法（三道防线）**：
1. **感知矩阵按需读取**：`collaboration.perception` 为每个角色声明必须感知的产物清单，Agent 动手前 `require()` 这些产物——不是全量黑板，而是「我这个角色需要知道的」。
2. **产物摘要受控截断**：`blackboard.brief()` 把每个产物 JSON 化后截断到 900 字符并显式标注「(截断, 共 N 字符)」，让模型知道「被截断了」而不是误以为这就是全部。
3. **经验注入双层 token 预算**：分层预算（L3 420 / L2 360 / L1 260）+ 全局总预算 1000 token（lean Profile 降到 600）；超预算的条目不静默丢弃，而是进 `skipped` 列表并注明原因（置信度不足 / 非本次运行 / 超条数 / 超预算），可审计「为什么这条经验没被注入」。
4. **补充手段**：消息 bus 只注入与该角色相关的摘要（`digest(role)`，默认 10 条 / 1600 字符），而不是全部通讯历史。
- **追问可答**：当前用中文 1 字 1 token、英文 3.2 字符 1 token 的启发式估算（无 tokenizer 依赖），精度有限但避免了引入 tiktoken 依赖；这是为「零第三方依赖」做的显式取舍。

### 难点 3：自学习闭环如何避免沦为「注了但没用」的摆设？

**问题**：很多所谓「记忆/经验」实现只是把历史教训拼进 Prompt，既无法证明它被采纳，也无法量化收益——注了和没注在行为上没有区别，就成了演示噱头。

**解法（四步让闭环可证伪）**：
1. **结构化动作标识**：每条经验除自然语言 `lesson`/`action` 外，额外带一个机器可读的 `action_key`（如 `avoid_missing_function_docstring`、`guard_calc_shipping__boundary`、`boundary_tri_state`），使「经验」从文本变成可执行信号。
2. **执行体真实消费**：离线确定性 Provider 在生成代码前读取本次注入的 `action_key` 集合，命中 `guard_*` 的功能点不再注入缺陷、命中 `avoid_*_docstring` 则首轮就补全文档字符串——经验直接改变生成行为，而不是靠模型「自觉」。
3. **全链路留痕**：每次 Prompt 落盘并记录注入的经验 ID、层级、token 数；`run_state` 累计 `injected_total` / `injected_tiers`；`llm_traces.jsonl` 记录思考链与原始输出（截断 12,000 字符）。
4. **收益可测量**：每轮运行把步数/回退/审查驳回/缺陷/耗时写入 `metrics.jsonl`，`improvement_summary()` 对比最近两次运行的差值，`learning_report.md` 输出「N 项指标下降，自学习闭环是否生效」的机械结论。离线回归实测：第二轮 11 步 / 0 缺陷 / 0 审查驳回，对比首轮 11→7 步、5→0 缺陷。
- **追问可答（诚实面）**：反馈闭环目前只接了一半——`reinforce()` 已实现但全仓库无调用点，置信度实际只通过「同源经验合并 +0.1」和「晋级 +0.05」增长；检索是关键词 + 标签打分，无向量语义召回，同义表述的经验召回不到。改进方向是引入 embedding 检索并打通「注入 → 行为变化 → 奖励回写」的在线反馈。

### 难点 4（备选）：门禁表达式来自配置文件，如何安全地求值？

**问题**：门禁规则写在 YAML 里（`test_report.coverage.boundary.rate >= 1.0`），直接用 `eval` 等于给配置文件开了一个任意代码执行的口子。

**解法**：用 `ast.NodeVisitor` 白名单实现求值器——只实现 `Constant / Name / Attribute / Subscript / BinOp / UnaryOp / BoolOp / Compare / IfExp / List / Tuple / Set / Dict / Call`（Call 还限定 14 个内置函数名），`generic_visit` 兜底拒绝其他一切语法节点，因此导入、赋值、lambda、推导式、属性赋值全部被禁。字段按点路径在黑板快照上取值，缺失时抛内部 `_MissingField` 并转成 `ExprResult(ok=False, error="字段缺失: xxx")`，保证门禁能给出可读失败原因而不是崩掉。此外在配置加载期就跑一遍语法 + 白名单校验，把问题拦在启动阶段。

## 五、写简历时的注意事项（避坑清单）

1. **不要说「使用了 LLM Function Calling / Tool Use」**——本系统未使用 function calling API。真实形态是「结构化输出契约 JSON + 确定性 Python 工具执行」，面试时这样说反而更能体现设计能力。
2. **不要声称「高并发 / 分布式」**——Leader 是单进程同步 `while` 循环，且 `_consult_factory` 依赖类属性，同进程内不能并行两个 run。
3. **不要编造通过率、耗时、团队规模、用户量**——这些代码里没有，用【待补充】。
4. **量化指标优先用可核实的**：6,789 行核心代码 / 5 个角色 Agent / 8 节点流水线 / 8 条门禁表达式 / 12 条静态分析规则 / 唯一依赖 PyYAML / 离线回归 11→7 步、5→0 缺陷。
5. **真实 LLM 模式的端到端稳定性是已知短板**：`metrics.jsonl` 中 2026-10-11 多条 `openai_compatible` 运行 `acceptance: false`（9~15 步、回退 3~9）。如果被问到，主动说明「长 JSON 生成 + 刚性门禁下的稳定性仍在优化，具体通过率【待补充】」，比回避更有说服力。
