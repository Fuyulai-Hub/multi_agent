# 简历精简版：配置驱动的多 Agent 任务协作系统（MAS）

> 2026-10-17 版。数字均来自当前代码库实查：核心 12,937 行 / 36 模块 / 333 个自测用例 / 42 次真实运行 / 138 条沉淀经验。详细版见 `docs/18`。

**项目名称**：配置驱动的多 Agent 软件交付流水线系统（MAS）

**一句话简介**：Leader 统一调度 5 个角色 Agent（产品 / 研发 / 评审 / 测试 / 报告），把「需求评估 → 方案设计 → 编码实现 → 代码审查 → 业务测试 → 缺陷修复 → 验收门禁 → 报告归档」8 节点交付流水线全链路自动化；第三方依赖仅 PyYAML。

**技术栈**：Python / Multi-Agent Orchestration（Leader-Worker）/ 配置驱动 / 黑板模式 / 消息总线 / AST 白名单安全求值 / 沙箱执行 / SSE 流式 / Function Calling / MCP / 零依赖前端（http.server）

## 核心职责与成果

**1. 配置驱动的流水线内核，流程拓扑零代码变更。**
用 YAML 声明节点 / 角色 / 流转边 / 门禁 / 回退策略；Profile 深合并 + 裁剪节点后自动重接流转边，`strict` 插入评审节点（8→9）、`lean` 裁剪审查节点（8→7、门禁 10→5 条）全程不改调度代码；配置加载期一次性校验节点引用、可达性、自环与表达式语法，把故障前置到启动阶段。5 个角色经版本化黑板 + 消息总线协作，零直接调用。

**2. 证据式验收门禁，把「模型声称通过」变成「跑出来通过」。**
AST 白名单求值器（仅放行无副作用表达式与内置函数，`generic_visit` 兜底拒绝一切副作用语法）在黑板快照上判定 10 条门禁表达式，叠加 21 条 AST 静态分析规则；五层沙箱防护（路径越界拒绝 / 命令白名单硬拒 shell / 敏感环境变量剥离 / rlimit 资源限制 / 外连依赖检测）执行测试与交付代码。

**3. LLM 客户端工程化（真实端点实测）。**
手写 urllib SSE 流式客户端绕开网关 300s 硬超时（非流式必 504，实测流式 422.5s 完整返回 4 万字符 JSON）；`reasoning_effort` 降级链（low→high）治理推理模型思考链打满 `max_tokens` 导致正文为空的问题；Function Calling 闭环（tool_calls → 沙箱执行 → 结果回灌 → 续跑）与 MCP（stdio/sse）工具通道经真实端点验证跑通。

**4. 自学习闭环 + Skill 体系。**
三级经验库（L1/L2/L3）按相关性 0.45 / 置信度 0.25 / 频次 0.15 / 新鲜度 0.15 加权检索，分层 token 预算注入；经验携带机器可读 `action_key`，由确定性执行体真实消费并改变生成行为（实测同需求第二轮步数 11→7、缺陷 5→0、审查驳回 1→0）；Skill 体系三阶段校验（元信息 → 参数 → 冒烟）+ 确定性匹配注入 + function calling 可执行轨，支持从真实运行产物自动沉淀新 Skill 复用。

## 项目亮点

- **零第三方依赖**：除 PyYAML 外全手写——SSE 流式解析、中文 bigram 经验检索（+ 同义词扩展）、http.server 前端控制台（运行监控 / 证据查看 / 技能开关热更新 / 任务取消，2,658 行纯标准库）。
- **全链路证据可追溯**：单次运行产出事件流、消息记录、Prompt 快照、LLM 追踪、产物全版本、沙箱 stdout/stderr、证据索引共 7 类证据。
- **安全与短板如实标注**：沙箱不提供网络隔离、Windows 无 rlimit 等价方案，均在代码与事件中明示降级；真实 LLM 模式下「长 JSON 生成 + 刚性门禁」通过率尚不稳定（offline 确定性模式稳定通过），不谎报。
