# 高性能内存分配器基准测试工具

## 背景

需要一个用 **C++17** 实现的基准测试工具，用于对比三种内存分配器（glibc malloc / jemalloc / tcmalloc）在高并发场景下的吞吐量与尾部延迟。

## 功能点

### FP-01 分配器抽象层
定义 `Allocator` 抽象基类，至少包含 `allocate(size_t)` / `deallocate(void*)` / `name()` 三个纯虚函数。
三个具体分配器各自继承实现。

### FP-02 内存回收与泄漏检测
统计每次分配与释放的字节数，工具退出时报告未释放字节总数；非零则退出码为 1。

### FP-03 并发压测引擎
支持 N 个线程（N 由命令行参数指定，默认 4）各自独立执行指定轮次（默认 100000 轮）的分配/释放循环，
所有线程共享同一个分配器实例。

### FP-04 延迟采样与分位数统计
记录每次分配的耗时（纳秒），提供 P50 / P95 / P99 / P999 四个分位数。
要求采样不引入额外分配（避免观察者效应）。

### FP-05 结果输出
以 JSON 输出：分配器名称、线程数、轮次、总字节数、吞吐量（ops/sec）、四个分位数。
JSON 必须可被 `json.loads` 解析。

### FP-06 命令行接口
`--allocator`（可选值：malloc / jemalloc / tcmalloc）、`--threads`、`--rounds`、`--output`（文件路径）。
缺少 `--allocator` 时报错并以退出码 2 退出。

## 非功能要求

- 必须使用 C++17 标准，不使用第三方依赖（jemalloc / tcmalloc 通过动态链接探测，缺失时降级为跳过并说明）
- 编译命令固定为 `g++ -std=c++17 -O2 -pthread -o bench main.cpp`
- 必须提供 CMakeLists.txt

## 待澄清问题

1. 分位数统计是否允许使用近似算法（如 t-digest）？还是必须精确？
2. 多分配器对比时，是每个分配器单独起进程，还是同一进程内依次跑？
3. jemalloc / tcmalloc 缺失时的"降级为跳过"，报告里应如何体现？

## 验收标准

1. 编译通过且无警告
2. 单线程 100000 轮无内存泄漏（退出码 0）
3. 四线程并发下不崩溃
4. JSON 输出字段完整且可解析
5. P50 <= P95 <= P99 <= P999 单调性成立
